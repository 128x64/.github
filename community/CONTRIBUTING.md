# Contributing to 128x64

Thank you for your interest in contributing to 128x64!

We welcome contributions from developers, designers, testers, writers, and community members. Whether you are fixing a bug, suggesting an improvement, writing documentation, or helping test a project, your contributions are appreciated.

These guidelines apply across 128x64 repositories and projects.

## 1. Ways to Contribute

We welcome contributions through GitHub Issues and Pull Requests, including:

- Source code and bug fixes.
- Documentation and writing improvements.
- Feature suggestions and improvements.
- UI and UX improvements.
- Testing and quality assurance.
- Translations.
- Design, accessibility, and usability improvements.
- Other relevant project improvements.

All contributions must relate to the project and comply with its applicable license and policies.

## 2. Before You Contribute

Before making a significant change, please open a GitHub Issue to discuss your proposal with the maintainers.

This helps us:

- Understand the proposed change.
- Determine whether it fits the project's direction.
- Avoid duplicate work.
- Discuss possible implementation approaches.

Small changes, such as typo fixes, minor documentation improvements, and straightforward bug fixes, may be submitted directly through a Pull Request.

Please read the repository's README and available documentation before asking questions or proposing changes.

## 3. Submitting a Pull Request

Pull Requests are the primary way to submit code and other repository changes.

Please ensure that your Pull Request:

- Has a clear and descriptive title.
- Explains what was changed.
- Explains why the change is necessary or useful.
- Identifies related Issues, where applicable.
- Includes relevant testing information.
- Mentions any known limitations or incomplete work.

Do not submit unrelated changes in one Pull Request unless they are necessary to accomplish the same objective.

## 4. Review and Approval

All Pull Requests are subject to review by an authorized 128x64 organization member.

Only authorized organization members may approve and merge Pull Requests or directly edit protected repositories.

Submitting a Pull Request does not guarantee acceptance.

Maintainers may request:

- Changes to the implementation.
- Formatting or structural adjustments.
- Additional documentation.
- Additional testing.
- Changes to the proposed scope.

Please respond constructively to review feedback.

## 5. Coding Standards

128x64 does not impose one universal coding style across every repository.

Contributors should initially follow the existing conventions and architecture of the repository they are working on.

Organization members and maintainers may request formatting, structural, architectural, or other changes when necessary.

Repository-specific instructions take precedence over general examples in this document.

## 6. Testing

Contributors should test their changes before submitting a Pull Request.

Include information about:

- What you tested.
- How you tested it.
- Whether the tests passed.
- Any known issues or limitations.

New functionality should include appropriate tests where practical.

Do not claim that tests passed if they were not performed.

## 7. Contributor Rights and Recognition

Contributors retain ownership of their original contributions.

By submitting a contribution, you agree to the Contributor License Grant in the repository's applicable LICENSE file.

This grant allows 128x64 to use, reproduce, modify, incorporate, maintain, and distribute accepted contributions as part of its projects and products.

Contributors may receive recognition in the relevant repository, documentation, or credits.

Submitting a contribution does not automatically grant permission to redistribute, independently reuse, or claim ownership of the complete project.

## 8. Repository Access and Usage

External contributors may participate through GitHub Issues and Pull Requests.

Unless separately authorized, external contributors do not receive direct repository editing or merging permissions.

The applicable repository license determines what access and usage permissions are granted.

Temporary local modifications necessary to prepare an authorized contribution are subject to the applicable license.

## 9. Joining the Organization

Individuals interested in becoming members of the 128x64 organization may request an invitation.

Membership is not automatic and is subject to review and approval.

We consider factors such as:

- Contribution quality.
- Reliability and consistency.
- Communication and collaboration.
- Understanding of 128x64 policies.
- Alignment with the organization's standards.

## 10. Community Expectations

All contributors must follow the 128x64 Code of Conduct and applicable repository policies.

We expect professional, respectful, and constructive communication.

Harassment, discrimination, threats, spam, malicious activity, and deliberate disruption are not tolerated.

## 11. Questions

If you have questions about contributing, please:

- Open a relevant GitHub Issue.
- Use GitHub Discussions where enabled.
- Contact us at raphaelcvarghese@gmail.com.
